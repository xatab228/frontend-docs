# Работа с инструментами ИИ — Junior

### Инструменты и помощники ИИ (копайлоты, чат-боты, редакторы текста)

Современный фронтенд-разработчик встречает ИИ-инструменты трёх основных типов. Копайлоты (GitHub Copilot, Cursor Tab, Codeium) встроены прямо в редактор кода и предлагают автодополнение строк или целых функций по мере набора текста, ориентируясь на контекст открытого файла и соседних файлов проекта. Чат-боты (ChatGPT, Claude, Gemini) работают в отдельном окне или встроенном чате IDE и отвечают на произвольные вопросы — от объяснения ошибки в консоли браузера до генерации React-компонента с нуля по текстовому описанию. Редакторы текста и документации на основе ИИ (Grammarly, Notion AI, встроенные ассистенты в Confluence) помогают формулировать комментарии к коду, PR-описания и техническую документацию. Для новичка важно понимать, что все эти инструменты — это подсказки, а не источник истины: предложенный код нужно читать и проверять, а не копировать вслепую.

```ts
// Пример: Copilot дописывает функцию по комментарию-подсказке
// написать функцию, которая форматирует цену в рублях
function formatPrice(value: number): string {
  return new Intl.NumberFormat('ru-RU', {
    style: 'currency',
    currency: 'RUB',
  }).format(value);
}
```

### Что такое промпт-инженеринг и его роль в взаимодействии с моделями

Промпт-инженеринг — это практика формулирования запроса (промпта) к языковой модели таким образом, чтобы получить максимально точный и полезный ответ. Модель не «понимает» задачу так, как человек, а генерирует наиболее вероятное продолжение текста на основе того, что ей дано на вход, поэтому качество и структура промпта напрямую влияют на качество результата. Хороший промпт обычно включает контекст (что за проект, какой стек), конкретную задачу, ограничения (например, "без внешних библиотек", "используй TypeScript strict mode") и, желательно, пример ожидаемого формата ответа. Для junior-разработчика важно на практике усвоить разницу между расплывчатым запросом и точным — это резко снижает количество итераций до рабочего результата.

```text
Плохой промпт:
"Напиши компонент кнопки"

Хороший промпт:
"Напиши React-компонент Button на TypeScript с пропсами
variant: 'primary' | 'secondary', onClick: () => void, disabled?: boolean.
Используй styled-components, следуй БЭМ-неймингу классов внутри styled.
Добавь JSDoc-комментарий к компоненту."
```

## Практика (УМЕЕТ)

### Устанавливать и использовать базовые инструменты ИИ (Copilot, ChatGPT) для автозаполнения и улучшения кода

Установка GitHub Copilot в VS Code выполняется через маркетплейс расширений: находим "GitHub Copilot", устанавливаем и авторизуемся через GitHub-аккаунт с активной подпиской. После установки Copilot начинает предлагать автодополнение прямо во время набора кода (подсвечивается серым текстом, принимается клавишей Tab), а через встроенную панель Copilot Chat можно попросить объяснить выделенный код, найти баг или сгенерировать unit-тест для функции.

```json
// .vscode/settings.json — базовая настройка Copilot в проекте
{
  "github.copilot.enable": {
    "*": true,
    "yaml": false,
    "plaintext": false
  },
  "editor.inlineSuggest.enabled": true
}
```

Для улучшения существующего кода достаточно выделить фрагмент и вызвать команду "Copilot: Explain This" или "Copilot: Fix" — модель предложит рефакторинг с объяснением, что именно было не так (например, отсутствие проверки на `null` перед обращением к полю объекта).

### Писать промты для получения нужной реакции от моделей

Демонстрация на практике того же принципа, что описан в разделе про промпт-инженеринг: чтобы получить конкретный код, а не общие рассуждения, промпт должен содержать роль, контекст, задачу и формат ответа.

```text
Промпт в ChatGPT/Claude:

"Ты — опытный frontend-разработчик, пишущий на React + TypeScript.
Контекст: есть список пользователей users: User[], каждый User
имеет id, name, email, isActive.
Задача: напиши хук useActiveUsers(users), который возвращает
только активных пользователей, отсортированных по имени.
Формат ответа: только код хука с типами, без пояснений."
```

Итеративное уточнение — тоже часть навыка: если первый ответ не подошёл (например, модель не учла сортировку), нужно не переписывать промпт с нуля, а указать точечную правку: "добавь сортировку по name.localeCompare(b.name)" — это ускоряет получение нужного результата и тренирует диалоговый стиль работы с моделью.
