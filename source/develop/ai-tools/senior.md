# Работа с инструментами ИИ — Senior

### Метод Chain of thoughts и принципы декомпозиции задач для LLM

Chain of Thoughts (цепочка рассуждений) — техника промпт-инженеринга, при которой модель явно просят рассуждать пошагово перед тем, как дать финальный ответ, вместо того чтобы сразу выдавать результат. Это резко повышает качество ответов на сложных задачах (алгоритмических, архитектурных), потому что модель, как и человек, чаще ошибается, пытаясь "угадать" ответ целиком, чем последовательно раскладывая задачу на шаги. Для senior-разработчика важно уметь декомпозировать крупную задачу на промпты так же, как декомпозируют тикет на подзадачи: сначала попросить модель спроектировать структуру данных, затем — написать функцию с этой структурой, затем — написать тесты, а не пытаться получить готовый сложный модуль одним запросом.

```text
Промпт с Chain of Thoughts:

"Реши задачу пошагово, прежде чем писать код:
1. Опиши, какие структуры данных нужны для LRU-кэша
2. Опиши временную сложность каждой операции (get, put)
3. Только после этого напиши реализацию класса LRUCache на TypeScript

Задача: реализовать LRU-кэш с O(1) на get и put."
```

```ts
// Результат декомпозиции — реализация на основе Map (сохраняет порядок вставки)
class LRUCache<K, V> {
  private capacity: number;
  private cache = new Map<K, V>();

  constructor(capacity: number) {
    this.capacity = capacity;
  }

  get(key: K): V | undefined {
    if (!this.cache.has(key)) return undefined;
    const value = this.cache.get(key)!;
    this.cache.delete(key);
    this.cache.set(key, value); // переставляем в конец — "свежий" элемент
    return value;
  }

  put(key: K, value: V): void {
    if (this.cache.has(key)) this.cache.delete(key);
    else if (this.cache.size >= this.capacity) {
      const oldestKey = this.cache.keys().next().value;
      this.cache.delete(oldestKey as K);
    }
    this.cache.set(key, value);
  }
}
```

### Принципы оптимизации кода, архитектуры и UI с ИИ агентами

При использовании ИИ-агентов для оптимизации важно задавать чёткий критерий "лучше" — иначе модель может оптимизировать не то, что нужно (например, сократить число строк ценой читаемости). Продуктивный подход: дать агенту конкретную метрику (время рендера, размер бандла, число ре-рендеров React-компонента) и попросить предложить несколько вариантов с trade-off'ами, а не один "правильный" ответ. Для UI-оптимизации агенты особенно полезны при поиске ненужных ре-рендеров через анализ дерева компонентов и пропсов, а для архитектурной оптимизации — при выявлении циклических зависимостей между модулями по графу импортов.

```text
Промпт для оптимизации React-компонента:

"Вот компонент ProductList, который ре-рендерится при каждом
изменении корзины, хотя список товаров не меняется.
Проанализируй причину лишних ре-рендеров и предложи 2 варианта
исправления: через мемоизацию и через изменение структуры state.
Укажи trade-off каждого варианта."
```

### Основы безопасности и регуляторные требования к использованию AI и защиты персональных данных (GDPR, CCPA и др.)

При интеграции ИИ в продукт важно понимать, что отправка пользовательских данных во внешний LLM-провайдер приравнивается к передаче данных третьей стороне, и на это распространяются GDPR (для пользователей ЕС) и CCPA (для пользователей Калифорнии): нужно правовое основание для обработки, возможность удаления данных по запросу пользователя, и прозрачность о том, что данные обрабатываются ИИ. Практические меры — не отправлять в промпт PII (email, номера телефонов, паспортные данные) без предварительной анонимизации, использовать провайдеров с опцией "не использовать данные для обучения моделей" (data retention off / zero data retention), и логировать сам факт использования ИИ на пользовательских данных для аудита.

```ts
// Простая анонимизация перед отправкой в LLM
function redactPII(text: string): string {
  return text
    .replace(/[\w.-]+@[\w.-]+\.\w+/g, '[EMAIL]')
    .replace(/\+?\d[\d\s\-()]{7,}\d/g, '[PHONE]');
}
```

## Практика (УМЕЕТ)

### Интегрировать ИИ-инструменты в процессы обеспечения качества

ИИ встраивается в pipeline качества как дополнительный, но не единственный, этап проверки: например, GitHub Action, вызывающий модель для ревью diff'а перед тем, как PR попадёт к человеку-ревьюеру, или агент, генерирующий недостающие тесты для непокрытых веток кода по отчёту coverage.

```yaml
# .github/workflows/ai-review.yml
name: AI Code Review
on: pull_request
jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run AI review on diff
        run: |
          git diff origin/main...HEAD > diff.patch
          node scripts/ai-review.mjs diff.patch
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

Такой шаг не заменяет человека, но ловит типовые проблемы (забытый `console.log`, отсутствие обработки ошибок) ещё до code review, снижая нагрузку на ревьюеров — прямое применение принципов из раздела про генерацию тестов и проверку кода, но уже на уровне CI, а не локальной разработки.

### Писать эффективные промпты для получения точных и релевантных ответов (RAG)

RAG (Retrieval-Augmented Generation) — подход, при котором перед генерацией ответа модели передают релевантные фрагменты из внешней базы знаний (документации проекта, векторной БД), найденные по семантическому поиску, вместо того чтобы полагаться только на "память" модели. Это критично для точности, потому что модель не обучена на приватной кодовой базе конкретной компании.

```ts
// Упрощённый пример RAG-пайплайна для ответа на вопрос по внутренней документации
async function answerWithRAG(question: string) {
  const relevantChunks = await vectorStore.similaritySearch(question, { topK: 3 });
  const context = relevantChunks.map((c) => c.text).join('\n---\n');

  const prompt = `Используй только приведённый контекст для ответа.
Если ответа нет в контексте, скажи "не найдено в документации".

Контекст:
${context}

Вопрос: ${question}`;

  return client.messages.create({
    model: 'claude-sonnet-4-5',
    max_tokens: 500,
    messages: [{ role: 'user', content: prompt }],
  });
}
```

Ограничение ответа явным "используй только контекст" — ключевой приём эффективного промпта, напрямую опирающийся на понимание ограничений LLM (галлюцинации) из раздела ЗНАЕТ.

### Учитывать этические аспекты и минимизировать риски (качество UI-кода, конфиденциальность данных и пр.)

На практике это означает: код, сгенерированный ИИ для UI, всегда проходит проверку на доступность (a11y) — модели нередко забывают про `aria-*` атрибуты и семантическую разметку; персональные данные пользователей маскируются функцией вида `redactPII` перед отправкой в промпт (см. пример выше); а в командных guideline фиксируется правило — какие данные категорически нельзя передавать во внешние ИИ-сервисы (платёжные данные, медицинская информация, данные под NDA), что напрямую реализует требования GDPR/CCPA из раздела ЗНАЕТ.
