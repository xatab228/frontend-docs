# Паттерны разработки — Junior

### Основные концепции ООП (объекты, классы, инкапсуляция, наследование, полиморфизм)

Объектно-ориентированное программирование строит систему из объектов — сущностей, объединяющих данные (поля/состояние) и поведение (методы) в одном блоке. Класс — это шаблон, описывающий, какие поля и методы будет иметь каждый созданный из него объект (экземпляр). Инкапсуляция — сокрытие внутреннего состояния объекта и предоставление доступа к нему только через публичные методы, что защищает данные от некорректного внешнего изменения и позволяет менять внутреннюю реализацию, не ломая внешний код. Наследование позволяет одному классу перенимать поля и методы другого, расширяя или переопределяя поведение без дублирования кода. Полиморфизм — способность объектов разных классов отвечать на один и тот же вызов метода по-разному, благодаря чему код может работать с объектами через общий интерфейс, не зная их конкретного типа.

```ts
class Shape {
  // инкапсуляция: приватное поле, доступное только внутри класса
  #color: string;

  constructor(color: string) {
    this.#color = color;
  }

  getColor(): string {
    return this.#color;
  }

  area(): number {
    return 0;
  }
}

// наследование: Circle расширяет Shape
class Circle extends Shape {
  constructor(color: string, private radius: number) {
    super(color);
  }

  // полиморфизм: переопределение метода area()
  override area(): number {
    return Math.PI * this.radius ** 2;
  }
}

class Square extends Shape {
  constructor(color: string, private side: number) {
    super(color);
  }

  override area(): number {
    return this.side ** 2;
  }
}

const shapes: Shape[] = [new Circle('red', 3), new Square('blue', 4)];
shapes.forEach((shape) => console.log(shape.area())); // каждый объект считает площадь по-своему
```

На практике эти принципы применяются при построении иерархии классов: базовый класс задаёт общий контракт (например, `area()`), а подклассы его реализуют, соблюдая инкапсуляцию, наследование и полиморфизм. Дополним иерархию абстрактным методом, чтобы явно запретить создание "абстрактной" фигуры без конкретной реализации:

```ts
abstract class Shape {
  protected constructor(private readonly color: string) {}

  abstract area(): number; // обязателен для переопределения в наследниках

  describe(): string {
    return `${this.constructor.name} цвета ${this.color}, площадь ${this.area().toFixed(2)}`;
  }
}

class Triangle extends Shape {
  constructor(color: string, private base: number, private height: number) {
    super(color);
  }

  override area(): number {
    return (this.base * this.height) / 2;
  }
}

const triangle = new Triangle('green', 6, 4);
console.log(triangle.describe()); // "Triangle цвета green, площадь 12.00"
```

Альтернатива в ФП-стиле — без классов, через объекты-описания и чистые функции, вычисляющие площадь по типу фигуры:

```ts
type ShapeData =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

const area = (shape: ShapeData): number => {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
  }
};
```

### Что такое функциональное программирование (ФП) и как оно отличается от ООП

Функциональное программирование — парадигма, где программа строится как композиция чистых функций, преобразующих данные, а не как набор взаимодействующих объектов с изменяемым внутренним состоянием. Ключевые идеи ФП: функции — это значения первого класса (их можно передавать как аргументы и возвращать из других функций), предпочтение неизменяемым (immutable) данным вместо мутации, минимизация побочных эффектов. В отличие от ООП, где состояние инкапсулируется внутри объектов и меняется методами, в ФП состояние обычно не хранится "внутри" функции — каждый вызов с одними и теми же аргументами даёт один и тот же результат. На практике во frontend-разработке (особенно в React) элементы ФП — иммутабельность, чистые функции рендера, `map`/`filter`/`reduce` — используются очень активно, даже если сам язык (JS/TS) мультипарадигменный.

```ts
// ООП-стиль: изменяемое состояние внутри объекта
class Counter {
  private count = 0;
  increment(): void {
    this.count += 1;
  }
}

// ФП-стиль: чистая функция, не мутирует входные данные, возвращает новое значение
const increment = (count: number): number => count + 1;

const cart = [{ id: 1, price: 100 }, { id: 2, price: 200 }];
// ФП: декларативное преобразование данных без мутации исходного массива
const total = cart.map((item) => item.price).reduce((sum, price) => sum + price, 0);
```

### О существовании разных подходов к проектированию ПО. Может перечислить некоторые из них

Помимо классического ООП и ФП, существует множество методологий и подходов к проектированию программного обеспечения, каждый со своей областью применения. К ним относятся: структурное программирование (декомпозиция на процедуры), декларативное программирование (описание "что" нужно получить, а не "как", например SQL или JSX), событийно-ориентированное программирование (реакция на события — типично для frontend и UI), реактивное программирование (потоки данных и распространение изменений, например RxJS), а также архитектурные подходы вроде MVC, компонентного проектирования (React/Vue-компоненты) и микросервисной архитектуры. На уровне junior достаточно знать, что такие подходы существуют и что выбор конкретного зависит от задачи — единого "правильного" подхода не существует.
