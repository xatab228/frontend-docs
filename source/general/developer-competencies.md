# Общие компетенции Developer

## ЗНАЕТ / УМЕЕТ по грейдам

### Жизненный цикл разработки ПО

**Trainee / Junior**

Знает:

- Общее понимание методологий разработки (Waterfall, Agile, Incremental, Iterative и др.), их плюсы и минусы, области применения
- Что такое Release, может назвать его этапы
- Что такое контроль версий и для чего он нужен
- Базовые техники работы с Git (клонирование репозитория, добавление, коммит и пр.)

Умеет:

- Подключаться к git-серверу, клонировать репозиторий
- Работать в пределах одной ветки

**Middle**

Знает:

- Подходы Agile-методологии (Scrum, Kanban), артефакты, особенности и различия
- Принципы декомпозиции задач и способы оценки трудозатрат
- Типы релизов (major, minor, hotfix, feature, patch) и их особенности
- Принципы организации рабочего процесса (GitFlow, trunk-based), их особенности
- Инструменты для управления проектами и репозиториями программного кода (GitLab, GitHub)

Умеет:

- Декомпозировать задачи на более мелкие подзадачи и оценивать трудозатраты
- Следовать работе по методологии Scrum и выполнять задачи в рамках спринтов
- Следовать принятым процессам release-менеджмента
- Применять основные команды и операции Git (clone, add, commit, branch, pull, push, reset и др.)
- Работать с инструментами управления проектами
- Объединять ветви и разрешать конфликты при слиянии

**Senior**

Знает:

- Принципы управления рабочим процессом в Jira или другом инструменте
- Категории оценки трудозатрат разработки, может назвать несколько инструментов и методик
- Варианты развертывания (blue-green, canary, rolling), их особенности
- Продвинутые техники работы с Git (cherry pick, bisect, stash, interactive rebase)
- Продвинутые возможности GitLab (merge request approvals, protected branches, CI pipelines)

Умеет:

- Вести техническую документацию
- Брать на себя ведущую роль в команде по методологии Scrum и проводить планирование
- Эффективно организовывать рабочий процесс с использованием ветвей, использовать fast forward merge (--ff-only) и cherry-pick

**Staff**

Знает:

- KPI для оценки эффективности работы команды и отдельных участников
- Принципы выбора оптимальной методики оценки трудозатрат в больших и/или комплексных проектах
- Принципы процесса и автоматизации релизов
- Концепции стандартизации методологий и инструментов работы с Git

Умеет:

- Декомпозировать сложные задачи и точно оценивать трудозатраты на комплексные изменения или целый продукт
- Проводить аудит и оптимизацию процессов разработки с использованием Agile-подходов
- Проводить анализ и улучшать процесс релиза
- Принципы создания самодокументирующегося кода
- Настраивать рабочий процесс GitFlow для команды разработчиков

### Обеспечение качества

**Trainee / Junior**

Знает:

- Основные типы тестов (unit tests, integration tests, UI tests, E2E и пр.)
- Что такое Unit Tests и зачем они нужны, принципы написания unit-тестов (независимость, атомарность, воспроизводимость)
- Методы контроля качества кода (статический анализ кода, динамический анализ кода)
- Что такое технический долг, причины его возникновения
- Принципы, цели и преимущества использования CI/CD
- Что такое Code Review и зачем он нужен
- О значимости поддерживаемости и читаемости кода

Умеет:

- Писать unit-тесты для проверки отдельного модуля или компонента
- Использовать инструменты статического анализа кода (линтеры)
- Проводить Code Review на соответствие Coding Best Practices
- Следовать правилам форматирования кода

**Middle**

Знает:

- Основы покрытия кода тестами (code coverage)
- Различные подходы к написанию unit-тестов (test doubles, stubbing, mocking)
- Методы обеспечения безопасности кода через статический анализ (SAST, DAST)
- Различия между качественным и некачественным сложно поддерживаемым кодом
- Когда и каким образом использовать комментарии
- Понятие качества в разработке ПО и важности внедрения процесса Quality Gates
- Принципы Clean Code

Умеет:

- Измерять процент покрытия кода тестами
- Писать Unit тесты, структурировать тестовые наборы и организовывать mock-объекты для unit-тестов
- Создавать тестовые сценарии для проверки различных условий и граничных случаев
- Применять различные методы контроля качества кода
- Анализировать кодовую базу на предмет наличия Техдолга (Tech Debt)
- Проводить Code Review на соответствие функциональности и качество кода
- Следовать лучшим практикам разработки (использование понятных и описательных имен переменных, функций и классов, написание информативных комментариев к коду и др.)

**Senior**

Знает:

- Методы тестирования взаимодействия между различными компонентами системы
- Особенности тестирования производительности кода с помощью авто-тестов
- Инструменты нагрузочного тестирования (например, JMeter, Gatling) и тестирования безопасности
- Продвинутые анализаторы кода (SonarQube, Coverity и др.)
- Техники и инструменты рефакторинга кода
- Инструменты CI/CD, может описать workflow с точки зрения разработчика
- Принципы настройки и контроля процессов качества
- Принципы, лежащие в основе принятия решений о дизайне системы и выбора шаблонов

Умеет:

- Настраивать автоматизированный запуск тестов и интегрировать их в процессы CI/CD
- Оптимизировать код на основе результатов тестирования производительности
- Реализовывать комплексные тесты, симулирующие реальные сценарии использования
- Настраивать инструменты проверки кода под требования проекта
- Применять инструменты для рефакторинга (IDE встроенные инструменты, плагины)
- Работать с legacy-кодом и модернизировать старую архитектуру
- Настраивать Quality Gates
- Проводить deep-dive reviews, выявляя архитектурные проблемы и подсказывая улучшения

**Staff**

Знает:

- Аспекты обеспечения качества на любом уровне (unit, integration, e2e)
- Новые тенденции и технологии в анализе кода и тестировании
- Стратегии повышения качества кода на уровне организации
- Влияние технического долга на сроки, бюджет и качество продукта
- Стратегии работы с Техдолгом (Tech Debt) (Strategic Debt Management)
- Принципы автоматизации и оптимизации процессов CI/CD
- Метрики и подходы контроля качества в процессе разработки ПО (скорость команды (velocity), количество дефектов, среднее время на исправление багов, ..)
- Стратегии создания Code Review culture

Умеет:

- Использовать инструменты для автоматизированного запуска тестов
- Создавать и оптимизировать процессы контроля качества кода
- Проводить масштабные рефакторинги в комплексных проектах
- Внедрять автоматизацию и инструменты для облегчения рефакторинга
- Создавать и поддерживать CI/CD пайплайны
- Управлять изменениями и реформами в культуре обеспечения качества
- Разрабатывать и продвигать стандарты разработки (style guides, лучшие практики, методологии)

### Работа с инструментами ИИ

**Trainee / Junior**

Знает:

- Инструменты и помощники ИИ (копайлоты, чат-боты, редакторы текста)
- Что такое промпт-инженеринг и его роль в взаимодействии с моделями

Умеет:

- Устанавливать и использовать базовые инструменты ИИ (Copilot, ChatGPT) для автозаполнения и улучшения кода
- Писать промты для получения нужной реакции от моделей

**Middle**

Знает:

- Ограничения ИИ, LLM и агентов, как выбрать подходящие сценарии использования
- Принципы использования ИИ для генерации тестов или проверки кода
- Основные сферы применения ИИ в продуктах (текстовые ассистенты, автоответчики и пр.)
- Методы интеграции ИИ в продукты (API, SDK, встраиваемые модули)

Умеет:

- Автоматизировать рутинные задачи (форматирование, базовое тестирование, простая генерация кода, документирование, code review) с LLM
- Применять AI Агентов встроенных в среду разработки (IDE) для написания и модификации кода
- Работать с ограничениями размера входных данных (контекстное окно) и оптимизировать запросы к модели

**Senior**

Знает:

- Метод Chain of thoughts и принципы декомпозиции задач для LLM
- Принципы оптимизации кода, архитектуры и UI с ИИ агентами
- Основы безопасности и регуляторные требования к использованию AI и защиты персональных данных (GDPR, CCPA и др.).

Умеет:

- Интегрировать ИИ-инструменты в процессы обеспечения качества
- Писать эффективные промпты для получения точных и релевантных ответов (RAG)
- Учитывать этические аспекты и минимизировать риски (качество UI-кода, конфиденциальность данных и пр.)

**Staff**

Знает:

- Принципы устройства инструментов и плагинов для интеграции ИИ, LLM и агентов, MCP (Model Context Protocol)
- Основные подходы к обучению моделей
- Принципы построения ИИ Workflow
- Принципы оптимизации ИИ агентов для специфических доменов, языков и дизайн-задач

Умеет:

- Интегрировать ИИ в рабочие процессы и CI/CD-пайплайны
- Определять стандарты и практики использования ИИ и агентов
- Проектировать и внедрять интеграцию ИИ в бизнес-продукты

### Структуры данных и алгоритмы

**Trainee / Junior**

Знает:

- Основные структуры данных (массивы, списки, связные списки, очереди, стеки)
- Несколько простых алгоритмов сортировки (пузырьком, шейкерная, расческой, вставками, выбором и др.)
- Понятие алгоритмической сложности (Big O notation)

Умеет:

- Работать с основными структурами данных и понимать области их применения

**Middle**

Знает:

- Продвинутые структуры данных (деревья, словари/хеш-таблицы)
- Принцип работы линейных и двоичных алгоритмов поиска, различия и области применения
- Разницу между временными и пространственными характеристиками алгоритмов
- Классы сложности алгоритмов (O(1), O(log n), O(n), O(n^2) и т.д.)

Умеет:

- Реализовывать продвинутые структуры данных и эффективно их использовать
- Применять алгоритмы сортировки и поиска и адаптировать их под конкретные потребности и ситуации
- Оценивать сложность алгоритмов и выбирать подходящую структуру данных

**Senior**

Знает:

- Операции для работы с деревьями и списками
- Способы ограничения скорости передачи данных (rate limiting)
- Способы профилирования и анализа производительности

Умеет:

- Реализовывать операции и алгоритмы для работы с деревьями и списками
- Выбирать наиболее подходящий алгоритм сортировки и поиска в зависимости от типа данных, объема сортируемых элементов и других факторов
- Ограничивать частоту операций простым способом (счетчиком и sleep)
- Проводить анализ производительности алгоритмов

**Staff**

Знает:

- Алгоритмы ограничения частоты операций (leaky bucket, token bucket)
- Принципы проектирования, разработки и оптимизации высокопроизводительных алгоритмов с минимальными затратами

Умеет:

- Разрабатывать и оптимизировать кастомные алгоритмы и структуры данных
- Эффективно управлять частотой операций и лимитировать запросы
- Измерять и улучшать производительность алгоритмов

### Паттерны разработки

**Trainee / Junior**

Знает:

- Основные концепции ООП (объекты, классы, инкапсуляция, наследование, полиморфизм)
- Что такое функциональное программирование (ФП) и как оно отличается от ООП
- О существовании разных подходов к проектированию ПО. Может перечислить некоторые из них

Умеет:

- Строить иерархию классов с соблюдением основных принципов ООП или ФП

**Middle**

Знает:

- Продвинутые техники ООП (abstract classes, interfaces)
- Принципы Inversion of Control (IoC), Dependency Injection (DI) и Dependency Lookup
- Понятия лямбда-функций и каррирования
- Принципы SOLID, DRY, KISS, YAGNI может расшифровать и объяснить назначение каждого из них
- Подходы проектирования (TDD, BDD, API First, Code first), их отличия и области применения
- Несколько из распространенных шаблонов проектирования и может описать области их применения (например, Singleton, Factory Method, Observer и др.)

Умеет:

- Проектировать и реализовывать объектно-ориентированные структуры данных и методы
- Применять принципы проектирования на практике
- Самостоятельно подбирать нужные шаблоны для реализации определенных требований

**Senior**

Знает:

- Плюсы и минусы ООП vs ФП
- Основные функции ФП (pure functions, immutability, higher-order functions, functions composition, рекурсия, мемоизация)
- Подробности работы распространённых шаблонов проектирования GoF, их плюсы и минусы
- Паттерн конфигурации Feature Toggles

Умеет:

- Минимизировать зависимости между компонентами, использовать IoC и DI для облегчения тестирования и поддержки
- Эффективно управлять общими компонентами, поддерживая правильный баланс между повторным использованием и сложностью
- Внедрять feature toggles для безопасных релизов и A/B тестирования

**Staff**

Знает:

- GRASP принципы
- Как сочетать ООП и ФП в одном проекте
- Лучшие практики сочетания шаблонов в крупных проектах
- Последние исследования и нововведения в области проектирования программного обеспечения

Умеет:

- Анализировать производительность кода с точки зрения ООП и вносить улучшения для оптимизации работы приложений
- Проектировать и разрабатывать масштабируемые и устойчивые системы, используя смешанный подход (ООП+ФП)
- Находить оптимальное сочетание архитектурных решений и качественных стандартов

### Архитектура

**Trainee / Junior**

Знает:

- Аспекты монолитной архитектуры и клиент-серверного подхода, понятие модульности
- Общая концепция паттернов MVC (Model-View-Controller) и MVVM (Model-View-ViewModel)
- Методы обработки и логирования ошибок
- Основные уровни логирования (debug, info, warning, error)

Умеет:

- Проектировать простейшие монолитные приложения

**Middle**

Знает:

- Особенности построения систем разного типа (Монолит, SOA, Микросервисы)
- Ключевые нефункциональные требования и показатели качества системы (доступность, отказоустойчивость, безопасность, масштабируемость, задержка, пропускная способность и пр.)
- Основные признаки высоконагруженных (highload) систем (большое количество пользователей, частые операции записи/чтения данных и пр.)
- Принципы мониторинга и трейсинга приложений
- Наиболее актуальные технологии наблюдаемости (например, Grafana, Prometheus, Jaeger)
- Эффективные инструменты логирования и анализа (например, ElasticSearch, Splunk, Sentry и др.)

Умеет:

- Проектировать и поддерживать SOA и микросервисные приложения
- Применять на практике хотя бы один паттерн presentation layer
- Использовать инструменты наблюдаемости
- Интегрировать логирование с системами мониторинга и алертинга

**Senior**

Знает:

- Продвинутые подходы проектирования (DDD, Clean Architecture)
- Особенности основных архитектурных паттернов (MVC, MVVM, MVP, CQRS, Saga, Pub-Sub, Event Sourcing, Microkernel), разницу между ними, плюсы и минусы
- Паттерны отказоустойчивости (rate limiting, circuit breaker, timeout, retry, fallback, bulkhead)
- Способы поддержания согласованности данных при одновременном доступе (concurrency)
- Принципы взаимодействия с системами мониторинга для создания наглядных дашбордов метрик и логов
- Требования к регистрации логов для соблюдения стандартов безопасности и конфиденциальности

Умеет:

- Применять на практике несколько архитектурных паттернов
- Собирать и анализировать подробную информацию о работе системы, находя скрытые проблемы и узкие места
- Использовать инструменты наблюдаемости (их настройка, администрирование и оптимизация)
- Проводить анализ и мониторинг логов для выявления проблем и оптимизации приложения
- Оптимизировать код и архитектуру для улучшения производительности
- Документировать архитектуру ПО

**Staff**

Знает:

- Современные технологии и тренды в области разработки архитектуры сложных масштабируемых систем: serverless, edge computing, или stream processing
- Методы тонкой настройки производительности и пропускной способности
- Инструменты и технологии построения высоконагруженных систем
- Принципы проектирования систем логирования для высоконагруженных и масштабируемых приложений
- Понятия SLA / SLO / SLI

Умеет:

- Проводить аудит и оценивать архитектуру существующих систем, выявляя слабые места и проводя необходимую модернизацию
- Проектировать системы с учетом SLA/SLO
- Создавать масштабируемые и отказоустойчивые решения с эффективным использованием логирования и метрик
- Определять и реализовывать эффективные стратегии хранения и анализа данных
- Создание и интеграция пользовательских метрик и алертинг на основе логов
- Проектировать системы контроля выполнения нефункциональных требований (метрики)

### Инфраструктура и Cloud

**Trainee / Junior**

Знает:

- Что такое облачная архитектура (cloud native), и чем она отличается от классической архитектуры
