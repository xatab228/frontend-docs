# Сборка и организация кода — Junior

### Что такое сборщик и зачем он нужен

Сборщик (bundler) — инструмент, который берёт набор исходных файлов проекта (JS, CSS, изображения и т.д.), анализирует зависимости между ними и объединяет в готовые для браузера артефакты. Он нужен, чтобы можно было писать код в виде модулей, использовать современный синтаксис и препроцессоры, а на выходе получать оптимизированные файлы, совместимые с целевой средой.

```bash
npm install --save-dev webpack webpack-cli
npx webpack --entry ./src/index.js --output-path ./dist
```
```js
// webpack.config.js
const path = require('path');

module.exports = {
  mode: 'development',
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
};
```
Запуск: `npx webpack` — собирает `src/index.js` со всеми зависимостями в `dist/bundle.js`.

### Основные различия между Webpack, Rollup, Vite, tsc

- **Webpack** — универсальный бандлер приложений, гибкий за счёт loaders/plugins, исторически медленнее в dev-режиме.
- **Rollup** — ориентирован на сборку библиотек, даёт компактный вывод благодаря отличному tree shaking.
- **Vite** — dev-сервер на нативных ES-модулях (мгновенный старт, без полной сборки в разработке), для production использует Rollup под капотом.
- **tsc** — компилятор TypeScript, не бандлер: транспилирует и проверяет типы, но не умеет объединять зависимости из node_modules в один файл.

### Что такое бандлинг

Бандлинг — процесс объединения множества исходных модулей и их зависимостей в один или несколько файлов (бандлов), пригодных для загрузки браузером. Позволяет использовать `import`/`require`, не заботясь о том, что браузер не умеет резолвить модули из node_modules напрямую.

### Базовые понятия транспиляции (например, TypeScript → JavaScript)

Транспиляция — преобразование кода из одного синтаксиса/версии языка в другой с сохранением семантики, например TypeScript → JavaScript или ESNext → ES5. В отличие от компиляции в машинный код, результат остаётся исходным кодом того же уровня абстракции. Для TS транспиляцию выполняет `tsc` или `babel` с пресетом `@babel/preset-typescript` (без проверки типов).

### Назначение базовых лоадеров (например, babel-loader, css-loader)

Webpack по умолчанию понимает только JS и JSON. Loaders — трансформаторы, которые превращают содержимое файла в валидный JS-модуль до включения его в граф.

- **babel-loader** — прогоняет JS/JSX/TS файлы через Babel, транспилируя современный синтаксис в код, совместимый со старыми браузерами.
- **css-loader** — разбирает `@import` и `url()` внутри CSS, превращает CSS в CommonJS-модуль, который можно импортировать из JS.
- Обычно в паре со `style-loader` (инжектит CSS в `<style>` тег) или `MiniCssExtractPlugin.loader` (выносит CSS в отдельный файл для production).

```js
// webpack.config.js
module.exports = {
  module: {
    rules: [
      { test: /\.jsx?$/, exclude: /node_modules/, use: 'babel-loader' },
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
    ],
  },
};
```

### Назначение плагинов (например, HtmlWebpackPlugin для генерации HTML)

Плагины расширяют возможности сборщика на уровне всего процесса сборки (а не отдельного файла, как loaders) — они подключаются к хукам жизненного цикла компиляции.

**HtmlWebpackPlugin** автоматически генерирует `index.html` и подставляет в него теги `<script>`/`<link>` со сгенерированными (с хэшами) именами бандлов.

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({ template: './src/index.html' }),
  ],
};
```

### Что такое минификация

Минификация — сжатие итогового кода за счёт удаления пробелов, комментариев, сокращения имён переменных и других безопасных преобразований, не меняющих поведение программы. Уменьшает размер файлов и, соответственно, время загрузки. В production-режиме Webpack и Vite включают минификацию (Terser для JS, cssnano для CSS) автоматически.

### Что такое Tree Shaking

Tree Shaking — техника удаления неиспользуемого кода (dead code elimination) из итогового бандла на основе статического анализа ES-модулей (`import`/`export`). Работает надёжно только с ESM, так как его структура импортов/экспортов статически анализируема, в отличие от динамического CommonJS.

### Что такое CommonJS и ES Modules

- **CommonJS (CJS)** — модульная система Node.js: `require()`/`module.exports`, разрешается синхронно и динамически в рантайме.
- **ES Modules (ESM)** — стандартная модульная система JavaScript: `import`/`export`, статически анализируется на этапе сборки, что позволяет делать tree shaking и поддерживается нативно в современных браузерах через `<script type="module">`.

### Что такое dev-сервер и зачем он нужен

Dev-сервер — локальный HTTP-сервер, поднимаемый сборщиком на время разработки: раздаёт собранные файлы, автоматически пересобирает изменённый код и обновляет страницу в браузере, часто умеет проксировать запросы к API. Избавляет от ручной пересборки и перезагрузки при каждом изменении.

### Что такое HMR (горячая замена модулей)

HMR (Hot Module Replacement) — механизм, при котором изменённый модуль заменяется в работающем приложении без полной перезагрузки страницы, сохраняя текущее состояние приложения (например, значения в форме или state компонента).

```js
// webpack.config.js
module.exports = {
  devServer: {
    static: './dist',
    hot: true,
    open: true,
  },
};
```
```bash
npx webpack serve
```
Во Vite HMR включён по умолчанию: `npm run dev` сразу поднимает dev-сервер с HMR без дополнительной настройки.
